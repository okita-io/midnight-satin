# Requirements Document

## Introduction

Midnight Satin is a premium romance reading web application designed as a "Tactile Noir Luxury" experience. The platform serves romance readers who value immersion, visual beauty, and curated content. It features AI-generated stories across multiple authors, series, and characters, with a credit-based economy for unlocking chapters and endorsing characters. The application is built with Next.js 16, React 19, TypeScript, and Tailwind CSS, deployed entirely on Vercel infrastructure (Vercel Postgres, Vercel Blob, Vercel KV). Content is generated by AI agents via an MCP interface. Six core screens — The Boudoir (Home), Novel Detail, The Reading Room, The Cast Gallery, The Author's Study, and The Vault (Store) — follow detailed HTML design mockups using the "Tactile Noir Luxury" design system (onyx backgrounds, metallic gold accents, mobile-first).

## Glossary

- **Platform**: The Midnight Satin web application as a whole
- **Boudoir**: The home/library screen serving as the main navigation hub
- **Novel_Detail_Screen**: The screen displaying a specific novel's summary, cast, and chapter list
- **Reading_Room**: The distraction-free reading screen for chapter content
- **Cast_Gallery**: The full-screen character profile viewer with endorsement functionality
- **Authors_Study**: The author biography and bibliography screen
- **Vault**: The credit purchasing store screen
- **Reader**: A user who consumes content on the Platform
- **Guest_Reader**: An unauthenticated user browsing the Platform
- **Registered_Reader**: An authenticated user with an account on the Platform
- **Author_Profile**: An AI-generated or manually created author persona with biography, style tags, and bibliography
- **Novel**: A single book belonging to a Series, composed of Chapters
- **Series**: A collection of related Novels by the same Author_Profile
- **Chapter**: A single unit of reading content within a Novel
- **Character**: A fictional persona within a Novel with portrait, backstory, and stats
- **Credit**: The virtual currency used to unlock Chapters and endorse Characters
- **Endorsement**: A "rose" given to a Character by a Reader, costing 1 Credit
- **Trophy**: A badge awarded to a Character when Endorsement count exceeds 1000
- **Veil**: The paywall overlay displayed at the end of free chapter content in the Reading_Room
- **MCP_Interface**: The Model Context Protocol API layer enabling AI agents to generate and manage content
- **Content_Agent**: An AI agent that creates stories, Author_Profiles, Characters, and Chapters via the MCP_Interface
- **Admin_Dashboard**: The administrative interface for content management, analytics, and user management
- **Design_System**: The "Tactile Noir Luxury" visual language defined in the PRD (colors, typography, textures, shadows)
- **Navigation_Bar**: The sticky bottom navigation bar present across all screens
- **Credit_Pack**: A purchasable bundle of Credits available in the Vault
- **Reading_Progress**: The tracked position of a Reader within a Chapter and Novel
- **ISR**: Incremental Static Regeneration, a Next.js rendering strategy for content pages
- **Vercel_Postgres**: The managed PostgreSQL database service on Vercel
- **Vercel_Blob**: The managed object storage service on Vercel for images and assets
- **Vercel_KV**: The managed Redis-compatible key-value store on Vercel for caching

## Requirements

### Requirement 1: The Boudoir (Home Screen)

**User Story:** As a Reader, I want a visually rich home screen that showcases featured novels, my current reads, and trending content, so that I can discover and resume reading easily.

#### Acceptance Criteria

1. THE Boudoir SHALL render a hero carousel section with a height of 350px or greater, displaying featured Novel cover images with vignette edges fading into the void background, matching the layout in `.antigravity/midnight_satin_home.html`
2. THE Boudoir SHALL display a "Current Affairs" section showing the Registered_Reader's currently reading Novel with cover image (2:3 aspect ratio), title in Playfair Display font, Author_Profile name in Marcellus font, current Chapter indicator, and a gold progress bar showing completion percentage
3. THE Boudoir SHALL display a "High Society" section with a horizontally scrollable list of trending Novels, each showing cover image, title, Author_Profile name, and optional star rating badge
4. THE Boudoir SHALL display a Vault teaser card promoting credit purchases with gold gradient styling
5. WHEN a Reader taps a Novel card in any section, THE Boudoir SHALL navigate to the Novel_Detail_Screen for that Novel
6. THE Boudoir SHALL render the sticky Navigation_Bar at the bottom with icons for Boudoir (active), Library, Vault, and Profile, where the active icon glows gold per the Design_System
7. WHEN the Boudoir has no content to display for a section, THE Boudoir SHALL show an empty state message in Pinyon Script font with gold color text
8. WHILE the Boudoir is loading content, THE Boudoir SHALL display shimmer placeholder animations in dark grey and gold gradient

### Requirement 2: Novel Detail Screen

**User Story:** As a Reader, I want to see a novel's full details including synopsis, cast, and chapter list, so that I can decide whether to read it and navigate to specific chapters.

#### Acceptance Criteria

1. THE Novel_Detail_Screen SHALL render a parallax hero section occupying 65% of the viewport height with the Novel cover image, gradient overlay fading to void black, and the Novel title in Playfair Display italic bold at 4xl size, matching the layout in `.antigravity/the_novel_detail.html`
2. THE Novel_Detail_Screen SHALL display metadata pills (genre tags) with 1px gold borders and primary gold text
3. THE Novel_Detail_Screen SHALL display a synopsis section with the first 3 lines visible and a "Read More" button that expands the full text inline
4. THE Novel_Detail_Screen SHALL display a "The Players" section with a horizontally scrollable list of circular Character portraits (80px diameter) with gold borders, each labeled with the Character name
5. WHEN a Reader taps a Character portrait, THE Novel_Detail_Screen SHALL open the Cast_Gallery modal for that Character
6. THE Novel_Detail_Screen SHALL display a chapter list where each Chapter shows its number, title, and access status ("Free" text or a gold lock icon for locked Chapters)
7. THE Novel_Detail_Screen SHALL display a floating action button (gold circle, 64px diameter) in the bottom-right corner that navigates to the Reading_Room for the first unread Chapter
8. WHEN a Reader taps a free Chapter in the chapter list, THE Novel_Detail_Screen SHALL navigate to the Reading_Room for that Chapter
9. THE Novel_Detail_Screen SHALL display the Author_Profile name as a tappable link that navigates to the Authors_Study

### Requirement 3: The Reading Room

**User Story:** As a Reader, I want a distraction-free reading experience with elegant typography and smooth chapter navigation, so that I can immerse myself in the story.

#### Acceptance Criteria

1. THE Reading_Room SHALL render chapter text in Literata font at 18px with 1.6 line-height, justified alignment, and 24px margins on a void black background, matching the layout in `.antigravity/the_reading_room.html`
2. THE Reading_Room SHALL render the first letter of each chapter as a drop cap in Playfair Display font at 3.5rem size in primary gold color
3. THE Reading_Room SHALL display ornamental dividers (filigree SVG in gold) between chapter sections
4. THE Reading_Room SHALL hide all navigation controls by default, showing only the reading text
5. WHEN a Reader taps the center of the Reading_Room screen, THE Reading_Room SHALL toggle the HUD overlay showing a header with back button and chapter title, and a footer with font settings, progress percentage, and chapter navigation controls (previous/next)
6. THE Reading_Room SHALL display a progress bar at the bottom of the footer HUD showing the Reader's position within the current Chapter as a gold line with glow effect
7. THE Reading_Room SHALL persist the Reader's scroll position as Reading_Progress so the Reader can resume from the same position on return

### Requirement 4: The Veil (Chapter Paywall)

**User Story:** As a Reader, I want a clear and elegant paywall mechanism that lets me unlock premium chapters with credits, so that I understand the value exchange.

#### Acceptance Criteria

1. WHEN a Reader scrolls past the free preview content in the Reading_Room, THE Reading_Room SHALL display the Veil overlay with progressively blurred text (1px, 3px, 6px blur levels) and decreasing opacity below the free content boundary
2. THE Veil SHALL display a lock icon, the heading "The Veil is Drawn" in Cinzel font, a thematic prompt message, and an "Unlock Chapter" button showing the cost of 5 Credits
3. THE Veil SHALL display the Reader's current Credit balance below the unlock button
4. WHEN a Reader taps the "Lift Veil" button and the Reader has 5 or more Credits, THE Platform SHALL deduct 5 Credits from the Reader's balance, remove the Veil with a gold dust particle animation, and reveal the full Chapter text
5. IF a Reader taps the "Lift Veil" button and the Reader has fewer than 5 Credits, THEN THE Platform SHALL display a prompt directing the Reader to the Vault to purchase more Credits
6. WHEN a Chapter is unlocked by a Reader, THE Platform SHALL permanently record the unlock so the Reader can re-read the Chapter without additional cost

### Requirement 5: The Cast Gallery

**User Story:** As a Reader, I want to explore character profiles with rich illustrations and backstories, so that I can connect more deeply with the story's cast.

#### Acceptance Criteria

1. THE Cast_Gallery SHALL render as a full-screen modal with a swipeable card interface occupying 75% of the viewport height, matching the layout in `.antigravity/the_cast_gallery_1.html`
2. THE Cast_Gallery SHALL display the Character portrait as a full-height background image with a gradient overlay fading to void black at the bottom
3. THE Cast_Gallery SHALL display the Character name in Playfair Display italic at 4xl size, a role subtitle (e.g., "The Exiled Heir") in Marcellus font, and a short description in italic body text
4. WHEN a Reader taps the "Tap to reveal dossier" prompt, THE Cast_Gallery SHALL perform a 3D card flip animation (700ms duration) revealing the backstory card with stats grid (Age, Status, Height, Occupation), known secrets section with burgundy accent bar, and background text
5. WHEN a Character has more than 1000 Endorsements, THE Cast_Gallery SHALL display an animated Trophy badge in the top-right corner with a pulsing gold glow effect on a 3-second cycle
6. THE Cast_Gallery SHALL display left and right navigation arrows on tablet and desktop viewports for browsing between Characters

### Requirement 6: Character Endorsement System

**User Story:** As a Reader, I want to endorse my favorite characters by sending roses, so that I can show appreciation and contribute to the community rankings.

#### Acceptance Criteria

1. THE Cast_Gallery SHALL display a rose endorsement floating action button (64px diameter, burgundy background) at the bottom center of the Character card
2. THE Cast_Gallery SHALL display the current Endorsement count below the rose button in Playfair Display bold gold text with an "Endorsements" label
3. WHEN a Reader taps the rose button, THE Platform SHALL display a confirmation prompt "Send a Rose? (1 Credit)"
4. WHEN a Reader confirms the endorsement and the Reader has 1 or more Credits, THE Platform SHALL deduct 1 Credit, increment the Character's Endorsement count by 1, display a "-1 Credit" toast notification, and animate the rose icon with a gold pulse effect
5. IF a Reader confirms the endorsement and the Reader has fewer than 1 Credit, THEN THE Platform SHALL display a prompt directing the Reader to the Vault
6. WHEN a Character's Endorsement count exceeds 1000, THE Platform SHALL award a Trophy badge to that Character and animate the Trophy badge onto the Character's Cast_Gallery profile

### Requirement 7: The Author's Study

**User Story:** As a Reader, I want to learn about authors and browse their complete bibliography, so that I can discover more stories I might enjoy.

#### Acceptance Criteria

1. THE Authors_Study SHALL display the Author_Profile avatar in a hexagonal mask with a gold gradient border, matching the layout in `.antigravity/the_authors_study.html`
2. THE Authors_Study SHALL display the Author_Profile name in Playfair Display italic at 3xl size, genre tags in Marcellus font, and stats row showing works count, follower count, and average rating
3. THE Authors_Study SHALL display the Author_Profile biography as a centered italic quote with decorative quotation marks and writing style hashtag pills
4. THE Authors_Study SHALL display a Trophy Case section as a 3-column grid showing the Author_Profile's earned trophies with icons, names, and descriptions
5. THE Authors_Study SHALL display the Author_Profile's bibliography grouped by Series, with each Novel showing cover image (80px x 112px), title, synopsis excerpt, rating, and publication year
6. WHEN a Reader taps the "Follow" button, THE Platform SHALL add the Author_Profile to the Reader's followed authors list and update the follower count
7. WHEN a Reader taps a Novel in the bibliography, THE Authors_Study SHALL navigate to the Novel_Detail_Screen for that Novel

### Requirement 8: The Vault (Credit Store)

**User Story:** As a Reader, I want to purchase credit packs to unlock chapters and endorse characters, so that I can continue enjoying premium content.

#### Acceptance Criteria

1. THE Vault SHALL display the Reader's current Credit balance as a large number in Playfair Display italic bold at 6xl size with a gold text gradient, matching the layout in `.antigravity/the_vault_store.html`
2. THE Vault SHALL display Credit_Pack options in a grid layout with the following packs: "Pouch of Dust" (50 Credits, $4.99), "Handful of Gold" (150 Credits, $12.99), "Chest of Riches" (500 Credits, $39.99), and "Royal Treasury" (1200 Credits, $89.99)
3. THE Vault SHALL visually highlight the "Handful of Gold" pack as "Most Popular" with a burgundy ribbon badge, elevated scale (1.02x), and a gold shimmer animation on the purchase button
4. WHEN a Reader taps a Credit_Pack purchase button, THE Platform SHALL initiate a payment flow through the configured payment provider
5. WHEN a payment is successfully completed, THE Platform SHALL add the purchased Credits to the Reader's balance and display a coin rain CSS animation as confirmation
6. IF a payment fails, THEN THE Platform SHALL display an error message and retain the Reader's original Credit balance unchanged
7. THE Vault SHALL display links to Terms of Service and Privacy Policy at the bottom of the store

### Requirement 9: Guest Access and Authentication

**User Story:** As a new visitor, I want to browse the app and read free chapter previews without creating an account, so that I can evaluate the platform before committing.

#### Acceptance Criteria

1. THE Platform SHALL allow Guest_Readers to browse the Boudoir, view Novel_Detail_Screens, and read Chapters marked as "Free" without requiring authentication
2. WHEN a Guest_Reader attempts to unlock a Chapter, endorse a Character, or access the Vault, THE Platform SHALL prompt the Guest_Reader to create an account or log in
3. WHEN a new Reader completes registration, THE Platform SHALL create a Registered_Reader account and grant 200 Credits as a welcome bonus
4. THE Platform SHALL support email-based authentication with secure password hashing
5. WHILE a Reader is authenticated, THE Platform SHALL maintain the session and display the Reader's Credit balance and Reading_Progress across all screens
6. WHEN a Reader logs out, THE Platform SHALL clear the session data and return the Reader to Guest_Reader state

### Requirement 10: Database and Data Models

**User Story:** As a developer, I want a well-structured database schema on Vercel Postgres, so that all content, user data, and transactions are stored reliably.

#### Acceptance Criteria

1. THE Platform SHALL store Author_Profile records in Vercel_Postgres with fields for id, name, avatar URL, biography, style tags, follower count, and creation timestamp
2. THE Platform SHALL store Series records with fields for id, title, Author_Profile reference, description, genre tags, completion status, and creation timestamp
3. THE Platform SHALL store Novel records with fields for id, title, Series reference, Author_Profile reference, cover image URL, synopsis, genre tags, rating, and publication date
4. THE Platform SHALL store Chapter records with fields for id, Novel reference, chapter number, title, content text, free/locked status, and creation timestamp
5. THE Platform SHALL store Character records with fields for id, Novel reference, name, role subtitle, portrait image URL, description, backstory, stats (age, status, height, occupation), secrets, endorsement count, and trophy status
6. THE Platform SHALL store Registered_Reader records with fields for id, email, password hash, display name, credit balance, creation timestamp, and last login timestamp
7. THE Platform SHALL store Reading_Progress records with fields for Reader reference, Chapter reference, scroll position percentage, and last read timestamp
8. THE Platform SHALL store Credit_Transaction records with fields for id, Reader reference, amount, transaction type (purchase, chapter_unlock, endorsement, welcome_bonus), related entity reference, and timestamp
9. THE Platform SHALL store Chapter_Unlock records with fields for Reader reference and Chapter reference to track permanent access
10. THE Platform SHALL store Author_Follow records with fields for Reader reference and Author_Profile reference

### Requirement 11: Content Delivery and Asset Storage

**User Story:** As a developer, I want efficient content delivery using Vercel infrastructure, so that readers experience fast load times for text and images.

#### Acceptance Criteria

1. THE Platform SHALL store all image assets (Novel covers, Character portraits, Author_Profile avatars) in Vercel_Blob with public read access
2. THE Platform SHALL serve Novel and Author_Profile listing pages using ISR with a revalidation period of 60 seconds
3. THE Platform SHALL cache frequently accessed data (trending Novels, featured content, Character endorsement counts) in Vercel_KV with a time-to-live of 300 seconds
4. THE Platform SHALL serve Chapter text content from Vercel_Postgres with server-side rendering for authenticated Readers
5. WHEN a new image asset is uploaded via the MCP_Interface or Admin_Dashboard, THE Platform SHALL store the asset in Vercel_Blob and return the public URL for database reference

### Requirement 12: MCP Interface for Content Agents

**User Story:** As a Content_Agent operator, I want an MCP interface that allows AI agents to create and manage all content types, so that the platform can be populated with generated stories at scale.

#### Acceptance Criteria

1. THE MCP_Interface SHALL expose a tool for creating Author_Profiles with name, biography, avatar image, and style tags as inputs, and return the created Author_Profile id
2. THE MCP_Interface SHALL expose a tool for creating Series with title, Author_Profile reference, description, and genre tags as inputs
3. THE MCP_Interface SHALL expose a tool for creating Novels with title, Series reference, cover image, synopsis, and genre tags as inputs
4. THE MCP_Interface SHALL expose a tool for creating Chapters with Novel reference, chapter number, title, content text, and free/locked status as inputs
5. THE MCP_Interface SHALL expose a tool for creating Characters with Novel reference, name, role, portrait image, description, backstory, stats, and secrets as inputs
6. THE MCP_Interface SHALL expose a tool for listing all Author_Profiles, Series, Novels, and Characters with optional filtering by Author_Profile or Series
7. THE MCP_Interface SHALL expose a tool for updating existing content records (Author_Profiles, Series, Novels, Chapters, Characters) by id
8. THE MCP_Interface SHALL validate all inputs against the database schema constraints and return descriptive error messages for invalid inputs
9. THE MCP_Interface SHALL support authentication via API key to restrict access to authorized Content_Agents

### Requirement 13: Admin Dashboard

**User Story:** As a platform administrator, I want a dashboard to manage content, view analytics, and manage users, so that I can operate the platform effectively.

#### Acceptance Criteria

1. THE Admin_Dashboard SHALL be accessible at the `/admin` route and require administrator authentication
2. THE Admin_Dashboard SHALL display a content overview showing total counts of Author_Profiles, Series, Novels, Chapters, and Characters
3. THE Admin_Dashboard SHALL provide CRUD interfaces for managing Author_Profiles, Series, Novels, Chapters, and Characters
4. THE Admin_Dashboard SHALL display user analytics including total Registered_Readers, active Readers (read in last 7 days), total Credits purchased, and total Credits spent
5. THE Admin_Dashboard SHALL display a list of Registered_Readers with search and filtering by email, registration date, and credit balance
6. THE Admin_Dashboard SHALL provide the ability to manually adjust a Registered_Reader's Credit balance with a reason field for audit logging
7. THE Admin_Dashboard SHALL display content analytics including most-read Novels, most-endorsed Characters, and top-followed Author_Profiles

### Requirement 14: Design System Adherence

**User Story:** As a designer, I want all screens to faithfully implement the Tactile Noir Luxury design system, so that the app delivers a consistent premium visual experience.

#### Acceptance Criteria

1. THE Platform SHALL use the following color palette across all screens: Primary gold (#D4AF37), void black (#050505), surface (#121212), text (#EAEAEA), muted (#8A8A8A), burgundy accent (#800020), and golden overlay (rgba(212, 175, 55, 0.08))
2. THE Platform SHALL use the following typography across all screens: Playfair Display 700 Italic for display titles, Cinzel 500 for headings with 1.5px letter-spacing, Literata 400 at 18px for body text, and Marcellus 400 at 14px for UI labels and buttons
3. THE Platform SHALL apply a subtle CSS noise texture overlay on dark surfaces to simulate fabric grain as specified in the Design_System
4. THE Platform SHALL use gold-tinted drop shadows (0px 4px 20px rgba(212, 175, 55, 0.15)) on elevated elements instead of standard dark shadows
5. THE Platform SHALL use sharp corner radii (2px for small elements, 4px for large elements) across all components
6. THE Platform SHALL implement a mobile-first responsive layout with a maximum content width of 448px (max-w-md) centered on larger viewports with dark border accents on the sides

### Requirement 15: Navigation System

**User Story:** As a Reader, I want consistent navigation across all screens, so that I can move between sections of the app without confusion.

#### Acceptance Criteria

1. THE Navigation_Bar SHALL be fixed at the bottom of the viewport on all primary screens (Boudoir, Library, Vault, Profile) with a void black background and a subtle top border
2. THE Navigation_Bar SHALL display four navigation items with Material Symbols icons: Boudoir (history_edu), Library (local_library), Vault (storefront), and Profile (person_3)
3. WHEN a Reader taps a Navigation_Bar item, THE Platform SHALL navigate to the corresponding screen and update the active icon to primary gold with a glow drop-shadow effect
4. THE Navigation_Bar SHALL not be visible on the Reading_Room screen or the Cast_Gallery modal to preserve the immersive experience
5. THE Platform SHALL display a header bar on the Boudoir with the "Midnight Satin" brand name in Cinzel font with a book icon, and search and notification action buttons

### Requirement 16: Reading Progress Tracking

**User Story:** As a Reader, I want my reading position saved automatically, so that I can resume reading exactly where I left off.

#### Acceptance Criteria

1. WHILE a Reader is reading in the Reading_Room, THE Platform SHALL save the Reader's scroll position as a percentage every 10 seconds to the Reading_Progress record
2. WHEN a Reader returns to a previously read Chapter, THE Reading_Room SHALL restore the scroll position to the last saved Reading_Progress percentage
3. THE Boudoir "Current Affairs" section SHALL display the Reader's most recently read Novel with the current Chapter number and completion percentage from Reading_Progress
4. THE Novel_Detail_Screen chapter list SHALL indicate which Chapters the Reader has started or completed based on Reading_Progress data

### Requirement 17: Vercel Deployment Configuration

**User Story:** As a developer, I want the application optimized for Vercel deployment, so that it leverages Vercel's infrastructure for performance and reliability.

#### Acceptance Criteria

1. THE Platform SHALL be configured for deployment on Vercel with Next.js 16 App Router
2. THE Platform SHALL use Vercel_Postgres as the primary database with connection pooling via the `@vercel/postgres` SDK
3. THE Platform SHALL use Vercel_Blob for all uploaded image assets via the `@vercel/blob` SDK
4. THE Platform SHALL use Vercel_KV for caching frequently accessed data via the `@vercel/kv` SDK
5. THE Platform SHALL configure environment variables for all Vercel service connections (POSTGRES_URL, BLOB_READ_WRITE_TOKEN, KV_REST_API_URL, KV_REST_API_TOKEN)
6. THE Platform SHALL use Edge-compatible middleware for authentication checks on protected routes
